# Project Context Brief

Generated by `sdgqalab-audit` on 2026-07-14T10:07:05Z.

## Product Purpose

- The repository is the SDG AI Lab public website with a browser-based admin CMS for non-technical editors, built as an Astro static shell with client-side React islands and Supabase-backed content reads and writes.
- Evidence: `README.md`, `src/pages/admin.astro`, `src/islands/admin/AdminApp.tsx`, `src/lib/queries.ts`, `src/lib/admin-queries.ts`.

## Primary Workflows

- Public visitors browse marketing pages, projects, news, team members, partners, and page content loaded from Supabase at runtime.
- Editors sign in via Supabase magic links and manage six content types plus media uploads under `/admin`.
- Evidence: `src/pages/index.astro`, `src/pages/projects/detail.astro`, `src/pages/news/detail.astro`, `src/islands/admin/auth/LoginPage.tsx`, `src/lib/storage.ts`.

## External Interfaces

- Public page routes are defined in `src/pages/`.
- Admin routing is hash-based inside `src/islands/admin/AdminApp.tsx`.
- External integrations are Supabase Postgres/Auth/Storage and GitHub Pages/GitHub Actions.
- Evidence: `src/pages/*.astro`, `src/islands/admin/AdminApp.tsx`, `.github/workflows/deploy.yml`, `.github/workflows/uptime-healthcheck.yml`.

## Data Contracts

- Public and admin data contracts are represented in TypeScript and SQL migrations rather than an HTTP schema owned by this repo.
- Schema constraints and RLS rules live in `supabase/migrations/001_initial_schema.sql` and `supabase/migrations/003_secure_editor_access.sql`.
- Admin API expectations are documented in `specs/002-admin-ui/contracts/admin-api.md`.

## Runtime Architecture

- Static site output is configured in `astro.config.mjs` with React and Tailwind integrations.
- Production deployment pushes to GitHub Pages from the `new-version` branch using repository secrets for public Supabase values.
- Availability monitoring is implemented as a scheduled GitHub Actions workflow that checks the public site and Supabase REST API.
